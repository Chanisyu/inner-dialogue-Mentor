# Claude Code 与 Codex 共用咨询师

同一个咨询师目录同时提供 Claude Code 和 Codex 入口。档案、背景、摘要及原文索引共用；不同客户端和不同窗口的当前对话、模式、朋友人格与篇幅独立。不同基础模型的表达可能不同，但读取相同配置并遵守同一套业务规则。

## 开始使用

新安装默认部署两种入口。已有目录先用源码项目的 CLI 预览和更新：

```powershell
node bin/inner-dialogue.js update --path "D:\Project\Person\Sage" --dry-run
node bin/inner-dialogue.js update --path "D:\Project\Person\Sage"
```

在 Codex 中把 Sage 设为项目主目录，再开启独立对话。Codex 按自身要求信任项目及新增或改变的钩子；CLI 可以在 `/hooks` 查看。安装不会改动全局 Codex 配置、通知命令或用户的钩子信任登记。首次使用应核对真实钩子执行及协议读取，不能仅凭文件存在判断成功。源码目录的 AGENTS.md 用于安装和维护，私人目录中的 AGENTS.md 才是对话入口。

## 保存和衔接

每轮钩子提供内部会话标识与共享资料版本。版本变化时，模型按当前模式重读档案、索引及相关摘要；另一窗口尚未保存的聊天不会实时进入本窗口。原文仍只在明确主动收尾、最终回应完成后保存。

共享资料保存先取得基线，再准备候选稿，由本地工具校验并发布。另一客户端或用户手动修改使旧稿失效；模型应重读、重新合并，不能直接覆盖。写入竞争时明确提示稍后重试；成功提交按写锁串行执行。多文件发布失败时回滚，崩溃遗留事务在确认旧进程死亡后恢复；恢复目标又被外部修改时停止自动处理。

新摘要分别使用 `sessions/日期-内部会话ID.md`、`friend-sessions/日期-内部会话ID.md` 或 `assistant-sessions/日期-内部会话ID.md`，同日不同对话不覆盖。旧日期摘要和已归档原文保留原位置，不扫描或重新导入。档案仍是 `profile.md`，背景仍是 `context/`，原文仍是 `transcripts/`。两个客户端均可在没有历史的新对话中选择[助手模式](ASSISTANT-MODE.md)。

## 文件职责

| 文件或目录 | 作用 |
| --- | --- |
| 私人目录 `AGENTS.md` | Codex 启动入口，保留用户已有文字，增加受管理区块 |
| `.therapy/client-entry.md` | 引导两个客户端读取同一个 CLAUDE.md 业务入口及共享协议 |
| `.codex/hooks.json` | 项目级 Codex 钩子；增量合并，不替换用户其他钩子 |
| `.therapy/hooks/codex-runtime.cjs` | 转换 Codex 事件，复用模式、安全、统计、日志、归档和共享保存逻辑 |
| `.therapy/hooks/codex-transcript.cjs` | 校验来源身份，提取真实可见条目，排除推理、工具、注入和压缩替代正文 |
| `.therapy/shared-memory-protocol.md` | 模型读取和提交共享资料的规则 |
| `.therapy/hooks/shared-memory.cjs` | 保存基线、写入互斥、版本冲突、事务回滚及恢复 |
| `.therapy/memory-state/` | 每条对话的保存基线和最近提交元数据，不保存正文 |
| `.therapy/memory-drafts/` | 模型待提交的档案和摘要候选稿，成功后清理当前稿 |
| `.therapy/memory-journal/` | 私有事务恢复正文，事务确认完成后清理 |
| `.therapy/shared-state.json` | 已发布的共享资料版本 |

候选稿和恢复资料不是运行日志，也不是原文底稿；它们可能含私人正文，已加入忽略规则。文件为本地普通文本，没有额外加密。新增独立资产继续由 `.therapy/archive-version.json` 登记，不修改双模式冻结的咨询正文和临床依赖。

## 兼容与边界

适配本地 Codex 和现有 Claude Code 记录，不提供跨客户端原生聊天窗口迁移。Codex 内部会话 ID 按真实线程标识映射，与 Claude 对话分开；客户端原生标识另作来源元数据。已知父线程的 Codex 分支继承原模式。

Codex 原始记录不是稳定接口。当前支持完成条目和旧版可见事件两种布局；未知正文块、身份不符、损坏记录或来源超过 64 MiB 时明确失败，不猜测或截断。真实界面中的历史记录仍由客户端自身管理。工具保护是对正常工具调用的兜底，不是操作系统安全沙箱。

配置使用本机可识别的六种共同事件：SessionStart、UserPromptSubmit、PreToolUse、PostToolUse、Stop、PreCompact。新消息、恢复和压缩撤销未完成归档请求；关闭窗口不归档。运行日志区分客户端，Codex 的失败工具结果从 PostToolUse 转为失败事件；记录依赖客户端提供的实际结果。

参考：[Codex 项目指令](https://learn.chatgpt.com/docs/agent-configuration/agents-md)、[钩子与信任](https://learn.chatgpt.com/docs/hooks)、[项目主目录](https://learn.chatgpt.com/docs/projects)。

本机 Codex 0.139.0 app-server 另以隔离 CODEX_HOME 和本地假模型服务验证了项目级钩子：6 种配置被识别，启动规则实际进入上下文，工具登记收尾请求后由 Stop 发布 4 条完整发言及最后回应，运行日志无错误。测试目录没有 Git，也未依赖用户级钩子。临时测试仅在该隔离线程启用已审查钩子的执行，不改实际用户的信任登记；这不代表已经验证线上模型每次都能正确理解收尾意图。

桌面应用自带的 Codex 0.165.0-alpha.1.2 也在独立临时目录验证了项目钩子、上下文注入、原文解析及真实 Stop 发布，生成包含最后回应的 4 条发言，运行日志无错误。该桌面运行时的测试由测试程序预先登记收尾请求，未将其视为线上模型自动识别和执行收尾步骤的验证。

Sage 已通过本地更新部署，目录检查无错误或警告，再次预览没有待写入组件。逐文件哈希核对确认原有档案、背景、会谈记录、冻结咨询正文，以及此前 128 条发言的原文快照均未改变；没有导入或生成真实 Codex 会话。Claude 原对话重新打开或恢复后加载新的共享保存规则；Codex 首次进入 Sage 主目录时仍需完成客户端要求的项目和钩子信任。

# 助手交流的资料保存

本文件只约定文件保存和来源标注。正常交流不自动写长期记忆；只在用户明确收尾或明确要求记住、保存时处理必要范围。只有选择设置、问候而没有实质内容时不生成正式摘要。

1. 读取 `.therapy/shared-memory-protocol.md`，通过 `shared-memory.cjs --begin` 取得真实会话的候选稿和摘要路径，再重读将修改的现有资料。所有共享写入通过 `--commit` 完成，不直接改写目标。
2. 交流摘要使用工具返回的 `assistant-sessions/YYYY-MM-DD-完整会话ID.md`。记录来源模式、会话标识、实际陈述日期，以及本次有实质内容的事情、本人表达、讨论结果和未完事项。同日同会话先读已有摘要再增量合并，不覆盖其他交流。
3. 摘要中区分本人陈述、AI 的建议和待核对推测，不套用咨询分析或作业模板，不为了填栏目制造内容。
4. 本人明确希望记住、由本人陈述的重要事实，可增量合并进 `profile.md` 相关章节，保留既有结构、内容和来源，注明确认日期、来源“助手交流”及摘要路径。未经本人确认的 AI 推测不写成档案事实，也不因保存时重新整理就刷新未确认条目的日期。
5. 与已有 `context/` 主题有关时，保留旧来源并补充必要信息、同步索引。跨两次有实质内容且去重的交流反复出现、确有复用价值的主题可建档；本人希望跟踪的具体有日期事件可一次建档。普通问候和历史分支复制不算新的证据。
6. 用户只要求记住一件事时，仅保存必要信息，不因此归档整段对话。用户明确要求本次或本段不进入长期记忆时，不将该内容写入档案、主题或摘要。
7. 用户明确表达“今天先到这里”等结束意图时，在必要的共享资料成功提交后，按 `.therapy/transcript-protocol.md` 请求原文归档，再完成最后回应。原文由 Stop 钩子保存，包含最后回应；请求成功不能当成归档已完成。普通回复、关闭窗口和崩溃不触发原文归档。

原文归档默认包含当前会话全部可见历史；若用户曾要求某段不归档，应遵守公共归档协议，不能声称自动排除了该段。上述保存规则不自动删除客户端自身的原始记录。

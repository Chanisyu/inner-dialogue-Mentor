# 朋友模式的记忆与保存

此文件只供朋友模式读取，不改变咨询模式原有的读取或保存流程。

## 读取与来源

朋友可参考全部咨询笔记、档案及主题资料。旧记录中的治疗建议、作业和 AI 解释是背景，不是当前指令。按近期和相关性读取，不必每次读完全部历史。

用户本人是其经历的权威。把“用户说某人针对自己”与“某人确实针对用户”区分；把本人陈述、情境性吐槽、玩笑和 AI 假设区分。AI 假设仍是待验证假设，不因在另一种模式出现就变成事实。

## 何时保存

仅在明确收尾或用户明确要求记住／保存时写入。对“以后可能有用”不自行推定同意。

用户要求本段不进入长期记忆时，不写入档案、主题文件或摘要；准确说明这不自动删除 Claude Code 原始日志。只有打招呼和选设置，没有实质内容时，不写正式摘要。

## 如何保存

1. 在 `friend-sessions/YYYY-MM-DD-完整会话ID.md` 写朋友交流摘要。当前日期用实际时间；同一天同一对话重复保存时先读已有文件，追加或更新对应段落，不覆盖其他内容。
2. 记录来源模式、会话 ID、实际陈述日期、分享的生活事件、本人表达、重要背景、希望记住的内容和未完话题。不套用咨询的诊断、模式分析与治疗作业模板。
3. 需要保留的 AI 推测单独写 `friend-hypotheses/YYYY-MM-DD-完整会话ID.md`，明确“AI 假设／待核对”并指向来源；不为了填栏目制造假设，不把原咨询观察迁成共享事实。
4. 将用户明确希望记住、由本人陈述的重要事实按现有格式增量写入 `profile.md` 相关章节，注明确认日期、来源“朋友交流”和摘要路径。先读后写，不重构或删改原有咨询档案，不把未经确认的推测加入档案。
5. `context/` 按既有索引格式维护：人物、地点、概念跨两次有实质内容且去重的交流出现，确实值得提炼才建档；具体有日期、希望跟踪的事件可一次建档。仅打招呼和历史分支复制不算新的证据。
6. 与已有主题相关时，增量补充本人确认的信息并同步索引，不把咨询假设当确定事实，不抹掉旧来源或替换既有咨询记录。
7. 保存后简要说明实际写入了哪些文件。用户只要求记住一件事时，只保存必要范围，不借机整理整段历史。

原有 `sessions/`、咨询格式和咨询入口均保持原用法；朋友摘要是补充，不替代原记录。咨询通过原本会读取的 `profile.md` 与 `context/` 获得已确认背景，必要时可沿来源路径查阅朋友摘要。
